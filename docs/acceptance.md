# Scooph 真机验收清单

> 计划 Task 26。每一条都是「操作 → 期望」；逐条执行并记录结果。
> 设备要求：Android 8.0+，允许安装未知应用；手机能访问 bucket 的 Git 地址。

## 首次启动

- [ ] 操作：清数据后首次打开 → 期望：无引导页、无提示文案；左上「来源」「全部更新」都在；主屏要么已有行，要么只有一句灰字「没有可管理的应用」。
- [ ] 操作：等待首次同步完成 → 期望：默认 bucket 已自动添加；与已装应用匹配的条目按「可更新 / 已是最新 / 已忽略」三组出现。

## 多来源

- [ ] 操作：来源页添加第二个 bucket → 期望：列表出现两行；条目数在同步后变化；右上「添加」输入行清空。
- [ ] 操作：同一个包在两个 bucket 里都有，且版本不同 → 期望：主屏只出现一行，取版本更高的条目；详情页「来源」显示生效条目的 bucket 名。
- [ ] 操作：删除最后一个 bucket → 期望：主屏只剩空状态；重新添加同一个 bucket 后，已有策略与跳过版本仍在（tracked 不随来源删除）。

## 策略

- [ ] 操作：详情页选「跳过这一版」 → 期望：该行进入「已忽略」，副行「已跳过 x」；上游发布更高版本、同步后 → 期望：自动回到「可更新」。
- [ ] 操作：详情页选「忽略后续更新」 → 期望：该行进入「已忽略」；之后同步不会把它改回「可更新」；手动改回「正常更新」才恢复。
- [ ] 操作：同一应用在两个页面进出详情页 → 期望：策略勾选状态一致。

## 单个更新

- [ ] 操作：在「可更新」行进入详情页点「更新到 x」 → 期望：系统安装确认框出现（没有我们自己的对话框）；确认后装好，返回后该行变「已是最新」。
- [ ] 操作：下载过程中取消（返回/锁屏后回来）→ 期望：这次不装，行回到「可更新」，不落任何状态。

## 一键更新

- [ ] 操作：可更新有 5 个应用时点「全部更新」 → 期望：不跳页；每行就地显示「正在下载 n% / 等你确认安装 / 已装好 / 跳过：… / 失败：…」；右上显示「已处理 / 总数」。
- [ ] 操作：其中一次在系统确认框点取消 → 期望：该项显示「跳过：已取消」，队列继续跑后面的。
- [ ] 操作：其中一次断网 → 期望：该项显示「失败：…」，队列继续；恢复网络后可再次更新。
- [ ] 操作：队列结束 → 期望：收到一条汇总通知（成功/跳过/失败计数），进行中不逐条发通知。
- [ ] 操作：队列进行中杀进程再打开 → 期望：队列消失（不落库），主屏按数据库状态正常显示。

## 签名与分包

- [ ] 操作：构造签名不一致的更新 → 期望：不提交安装，该行显示「签名已变更」，队列在此停住；详情页出现「接受并更新」。
- [ ] 操作：对分包安装（split APK）的应用尝试更新 → 期望：跳过并写明「该应用为分包安装，暂不支持」，不安装。

## 条目页与首次安装

- [ ] 操作：来源页点进一个 bucket → 期望：顶部搜索框常驻；查询 `k9` 与 `com.fsck` 都命中 K-9 Mail；已安装的行排在前面。
- [ ] 操作：点未安装的行 → 期望：直接进入下载 → 系统确认 → 装好；不跳详情页；装完主屏出现该行（FOLLOW）。
- [ ] 操作：点已安装的行 → 期望：进入详情页，与主屏进入的是同一个页面。

## 深色模式

- [ ] 操作：`adb shell "cmd uimode night yes"` → 期望：主屏三组、详情页、来源页、条目页文字与背景对比清晰，强调色只出现在当前状态与主操作；切回 `night no` 正常。

### 已修复的验收缺陷

1. **详情页「更新」按钮没接线**：`DetailScreen` 的 `onUpdateClick` 默认空实现，点按无反应。改为直接调用 `DetailViewModel.update()`。
2. **安装被卡在「等待用户确认」**：`PackageInstaller` 返回 `STATUS_PENDING_USER_ACTION` 时，需要用 `EXTRA_INTENT` 拉起系统确认界面；原实现把它当失败返回。现在会拉起确认页，并等同一个 PendingIntent 的最终结果（10 分钟超时）。
3. **更新过程无反馈**：详情页现在显示「更新中… / 正在下载 n%」以及失败原因；`logcat -s ScoophUpdate` 会记录最终结果。
